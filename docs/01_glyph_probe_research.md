# 汉字字形可解码性研究方案

## 1. 项目摘要

本项目研究一个冻结预训练语言模型的隐藏状态中，是否包含可以被简单输出层恢复的汉字字形信息，以及原生多模态预训练是否会增强这种信息。

模型主体、Token Embedding 和所有中间层均保持冻结，只移除或绕过原始词表输出头，新增一个预测 32×32 二值点阵的输出头：

```text
中文输入
  ↓
冻结的预训练模型
  ↓
目标位置隐藏状态 h ∈ Rᵈ
  ↓
Linear(d, 1024)
  ↓
reshape(32, 32)
  ↓
Sigmoid + 二值化阈值
```

第一阶段研究“输入汉字能否恢复未见汉字的字形”；第二阶段研究“纯中文语义上下文能否预测下一个汉字的字形”。

## 2. 核心研究问题

1. 纯文本预训练模型的隐藏状态中是否存在可线性解码的汉字字形信息？
2. 这种信息是字符身份记忆，还是能够泛化到未参与输出头训练的汉字？
3. 原生多模态预训练是否使文本隐藏状态包含更多汉字字形信息？
4. 更大的汉字 Token 覆盖是否会提高字形恢复能力？
5. 字形信息主要存在于浅层、中间层还是最后一层？
6. 在只提供中文语义上下文、目标汉字不出现在输入中时，模型能否生成合理字形？

## 3. 研究假设

- H1：冻结模型的隐藏状态可以恢复训练过的汉字点阵，但未见汉字表现会明显下降。
- H2：对于部件已见但组合未见的汉字，模型表现优于完全未见部件的汉字。
- H3：Qwen3.5 的原生多模态训练和更大词表会提升字形可解码性。
- H4：在两个 tokenizer 都将目标汉字编码为单 Token 的交集上，Qwen3.5 仍会优于 Qwen3；若差异消失，提升主要来自 tokenizer 覆盖。
- H5：普通像素准确率会高估模型能力，前景 F1、IoU 和最近汉字检索准确率更能反映真实表现。

## 4. 模型选择

### 4.1 开发模型

[Qwen3.5-2B-Base](https://huggingface.co/Qwen/Qwen3.5-2B-Base)

- 用于跑通 tokenizer 分析、数据管线、隐藏向量提取和输出头训练。
- 文本隐藏维度为 2048，共 24 层。
- 与正式主模型使用相同的 Qwen3.5 混合架构，能提前发现兼容性问题。

### 4.2 正式主模型

[Qwen3.5-4B-Base](https://huggingface.co/Qwen/Qwen3.5-4B-Base)

- 语言模型参数约 4B，完整模型包含视觉编码器，共约 5B 参数。
- 文本隐藏维度为 2560，共 32 层。
- 词表大小为 248,320。
- 架构为 Gated DeltaNet 与全注意力混合结构。
- 官方模型为原生多模态 Causal Language Model with Vision Encoder。
- Apache-2.0 许可证。

本项目只输入文本。视觉编码器不参与前向计算，可放在 CPU，或只加载 `text_config` 对应的语言部分。多模态预训练可能已经影响文本隐藏状态，这正是需要测量的研究变量。

### 4.3 关键对照模型

[Qwen3-4B-Base](https://huggingface.co/Qwen/Qwen3-4B-Base)

- 纯文本因果语言模型。
- 文本隐藏维度同样为 2560，共 36 层。
- 词表大小为 151,936。
- Apache-2.0 许可证。

Qwen3 与 Qwen3.5 的隐藏维度相同，因此可使用参数量完全一致的 `Linear(2560, 1024)` 输出头。两者对比可以测量多模态训练、架构更新和 tokenizer 扩展带来的综合变化。

### 4.4 暂不使用 Qwen3.8

[Qwen 官方当前的 Qwen3.8 型号](https://huggingface.co/Qwen/models?search=Qwen3.8)主要包括 27B、180B 和更大的 MoE 模型，目前没有适合 16GB 显存的小型 2B/4B Base 型号。

Qwen3.8-27B 的 BF16 权重远超本机显存；INT4 权重本身也接近 16GB 上限，运行缓存和中间张量没有足够空间。量化还会改变隐藏状态，干扰跨模型研究结论。因此第一阶段不使用 Qwen3.8。未来若官方发布 Qwen3.8-4B-Base，可在不改变数据和输出头设计的情况下加入第三组实验。

## 5. 硬件与运行策略

本机 GPU：RTX 5060 Ti 16GB。

推荐设置：

```text
模型主体精度：BF16
输出头精度：FP32
上下文长度：MVP 使用 64，第二阶段测试 128
特征提取 batch：从 2 或 4 开始，逐步测试 8/16
use_cache：false
Attention：PyTorch SDPA
模型主体梯度：关闭
输出头梯度：开启
```

Windows 下优先使用支持 RTX 50 系列和相应 CUDA 架构的 PyTorch 官方构建。第一版不依赖 FlashAttention 和 bitsandbytes，以减少环境和量化变量。所有 Python 环境由 `uv` 管理。

Qwen3.5-4B-Base 完整 BF16 权重约需 10GB 原始存储空间；纯文本语言部分约为 4B 参数。模型主体不反向传播时，16GB 显存足以处理短上下文。输出头和 AdamW 优化器只占用很少显存。

## 6. 输出层与训练目标

对于 Qwen3.5-4B-Base 和 Qwen3-4B-Base：

```text
输入维度：2560
输出维度：1024
权重数量：2560 × 1024
偏置数量：1024
总参数量：2,622,464
```

输出的每一维代表 32×32 点阵中的一个位置。训练时输出 Logit，不在模型内部提前二值化：

```python
logits = glyph_head(hidden_state)
logits = logits.reshape(-1, 32, 32)
probabilities = logits.sigmoid()
binary_bitmap = probabilities >= threshold
```

主损失建议采用：

```text
加权 BCEWithLogitsLoss + Dice Loss
```

前景笔画像素少于背景像素，必须根据训练集统计设置正样本权重。二值化阈值由验证集选择，不能直接假设 0.5 最优。

## 8. 数据集 A：HanziGlyph-8K

### 8.1 目标

建立约 7,000～10,000 个汉字与固定 32×32 二值字形之间的映射，用于冻结模型的字形可解码性实验。

```text
输入：清
目标：清在 Noto Sans CJK SC Regular 中的 32×32 二值点阵
```

### 8.2 字符选择

1. 从 Unihan 获得候选字符。
2. 使用中文维基语料统计字频。
3. 只保留 Noto Sans CJK SC 有真实字形的字符。
4. 排除控制字符、兼容字符异常、缺字方框和不可稳定渲染字符。
5. 保留常用字、低频字和生僻字三个频率层次。
6. 分别记录简体、繁体、异体和 Unicode 扩展区。

### 8.3 确定性点阵生成

- 使用固定字体文件，而不是系统字体名称。
- 使用固定版本的 FreeType/Pillow 渲染。
- 固定字号、画布、基线、水平垂直居中规则。
- 先渲染灰度图，再使用固定阈值生成二值图。
- 保存渲染器版本、字体 SHA-256、阈值和边界规则。
- 检测所有字符是否误渲染成相同的 tofu 缺字框。

## 9. 数据集 B：ChineseContext-Glyph

### 9.1 目标

构建纯中文上下文到下一个汉字点阵的预测任务：


### 9.2 MVP 规模

```text

目标汉字：3,000～5,000
每字上下文：尽量保持 20～100 条
上下文长度：32～128 Token，首轮固定 64
```

确认存在有效信号后，再扩展到 1,000,000 条样本。

### 9.3 清洗规则

- 解析维基 XML，只保留正文。
- 删除模板、HTML、URL、引用、表格、代码和导航内容。
- 使用 NFC 规范化；避免会改变兼容汉字的过度规范化。
- 使用 OpenCC 转换为简体，同时保存原始文本和转换版本。
- 中文汉字和中文标点占比建议至少 85%。
- 删除乱码、超长重复、广告和近重复段落。
- 按来源文章划分数据，避免同一文章跨训练集和测试集。
- 对高频字设置每字采样上限，避免“的、是、了”等字符支配数据集。
- 不对低频字简单复制过采样；优先寻找更多独立上下文或在损失中加权。

## 10. Tokenizer 与隐藏状态对齐

对全部候选汉字生成 tokenizer 报告：

- 单 Token 字符。
- 多 Token 字符及 Token 数量。
- 简繁体和生僻字覆盖。
- Qwen3 与 Qwen3.5 单 Token 字符交集。

主报告至少包含两组结果：

1. Native：使用每个模型自己的全部有效字符。
2. Intersection：只使用在两个 tokenizer 中均为单 Token 的字符。

多 Token 汉字可采用“最后一个子 Token 隐藏状态”和“所有子 Token 平均池化”两种方式，并作为独立消融实验，不能与单 Token 结果混在一起。

## 11. 数据拆分与防泄漏

### 11.1 随机字符拆分

按字符而不是样本拆分：

```text
训练字符：70%
验证字符：15%
测试字符：15%
```

同一个目标汉字的所有上下文只能出现在一个集合中。

### 11.2 构件组合拆分

利用 IDS 将测试集构造成：

- 语义部件已见、声旁已见、组合未见。
- 部分部件未见。
- 整体结构类型已见与未见。

该拆分用于区分“字符查表”与“构件组合泛化”。

### 11.3 字频拆分

- 高频训练、低频测试。
- 高频/中频/低频分桶报告。
- 字频由本次清洗后的中文维基语料重新统计，不依赖不可复现的第三方频率表。

### 11.4 上下文拆分

另外建立一个目标字符可重叠、但来源文档不重叠的普通上下文拆分，用于测量标准的上下文预测能力。该结果不能代替字符不重叠实验。

## 12. 冻结模型与隐藏向量缓存

模型主体设置为 `eval()`，所有参数 `requires_grad=False`。使用 `torch.no_grad()` 提取目标位置隐藏状态，再与输出头分开训练。

建议先离线缓存隐藏状态：

```text
Qwen3.5-4B hidden_size：2560
BF16 每条隐藏向量：2560 × 2 = 5120 字节
20 万条：约 1.0GB
100 万条：约 5.1GB
```

缓存后可卸载语言模型，只用输出头重复测试不同损失、阈值和数据拆分。隐藏特征应按模型、层号、tokenizer 版本、输入模板和数据版本分目录保存，避免误用。

## 13. 分层探针

除最后一层外，为以下归一化深度训练独立线性头：

```text
Embedding 输出
25% 深度
50% 深度
75% 深度
最后一层
```

每个探针都使用相同数据拆分、相同参数初始化策略和相同训练预算。Qwen3 与 Qwen3.5 层数不同，因此按相对深度比较，不直接按层号比较。

## 14. 对照实验

至少包含：

1. 正确的冻结模型隐藏状态 → 正确点阵。
2. 冻结随机初始化模型 → 正确点阵。
3. 正确隐藏状态 → 随机打乱的汉字点阵。
4. Token ID Embedding 查表 → 点阵。
5. 原始 LM Head 预测 Token → 查表转换为点阵。
6. 单线性层与两层 MLP 输出头对比。
7. Qwen3 与 Qwen3.5 在单 Token 交集字符集上的对比。

线性输出头是主要结果。MLP 只能作为“是否存在非线性可恢复信息”的补充实验。

## 15. 评测指标

不能只报告普通像素准确率，因为背景点远多于笔画点。

主要指标：

- 前景像素 Precision、Recall、F1。
- Intersection over Union（IoU）。
- Dice 系数。
- 完整 1024 位点阵匹配率。
- Hamming 距离。
- 最近字形检索 Top-1/Top-5 准确率。
- 最近字形是否具有正确部首、IDS 结构和笔画范围。

所有指标按以下分桶分别报告：

- 高频、中频、低频。
- 单 Token、多 Token。
- 简体、繁体、异体。
- 左右、上下、包围、独体等结构。
- 已见部件组合、未见组合、未见部件。

使用 bootstrap 计算置信区间。模型选择和二值化阈值只依据验证集，测试集只运行最终配置。

## 16. 自回归限制

1024 位点阵不能直接作为下一步的 Token 输入。第一阶段的任务是单次探针和下一字符点阵预测，不进行自由运行的长文本生成。

若未来需要连续生成，可以：

1. 将输出点阵与候选字形库做最近邻匹配，得到 Unicode 字符后重新 tokenizer；或
2. 保留原始 LM Head，并同时增加 Glyph Head；或
3. 训练点阵输入编码器，但这会改变输入侧，不再属于“只改输出层”的当前研究。

## 第二部分：Qwen3.5-2B 冻结模型字形探测实验报告

# Qwen3.5-2B 汉字 32×32 点阵冻结线性探针实验报告

## 1. 摘要

本实验研究：冻结 `Qwen/Qwen3.5-2B-Base` 的全部预训练参数后，单个汉字的隐藏状态能否通过一个线性输出头恢复为 32×32 二值字形。

实验使用 5,500 个互不重复、被 Noto Sans CJK SC 支持且被 Qwen3.5 tokenizer 编码为单 Token 的汉字。数据按字符随机划分为训练 3,850 字、验证 825 字、测试 825 字，同一个汉字不会跨集合出现。模型骨干全程冻结，只训练 `Linear(2048, 1024)`。

结论分为两部分：

1. 最后层隐藏状态确实包含显著的字符判别/字形身份信号。测试集最近字形检索 Top-1 为 7.03%，显著高于打乱标签和随机机会的 0.12%。
2. 该信号尚不足以忠实重建未见汉字。最后层前景 F1 为 0.4598，低于平均字形基线的 0.5804，825 个测试字的完整 1024 位匹配率为 0。

输入 Embedding 的检索 Top-1 达到 19.76%，明显高于最后层的 7.03%。这说明字形身份信息更多存在于词元嵌入中，经过模型层后有所减弱，但没有完全消失。

## 2. 研究问题与判定标准

本轮实验回答三个问题：

1. 冻结模型的最后层隐藏状态能否在线性映射下跨未见字符泛化？
2. 可恢复信息是否超过“输出所有汉字的平均形状”与“随机标签”对照？
3. 字形身份信号主要存在于输入 Embedding，还是经过模型计算后的最后层？

“存在信号”与“能忠实画出汉字”必须分开判断：

- 前景 F1、IoU、Hamming 距离衡量像素重建质量。
- 最近字形检索衡量预测结果是否包含目标字符特异信息。
- Exact Match 要求 1024 个二值点全部正确，是最严格的重建指标。
- 普通像素准确率不能单独作为结论，因为背景像素和汉字共有轮廓会造成虚高。

## 4. 模型与训练方法

### 4.1 冻结骨干

| 项目 | 值 |
|---|---|
| 模型 | `Qwen/Qwen3.5-2B-Base` |
| revision | `b1485b2fa6dfa1287294f269f5fb618e03d52d7c` |
| 模型类 | `Qwen3_5ForCausalLM` |
| hidden size | 2048 |
| 骨干精度 | BF16 |
| Attention | PyTorch SDPA |
| 骨干梯度 | 全部关闭 |
| 输出头 | `Linear(2048, 1024)` |
| 输出头参数量 | 2,098,176 |

对每个单 Token 汉字提取两种特征：

- `last_hidden`：最后层目标位置隐藏状态。
- `input_embedding`：同一 Token 的输入 Embedding。

所有特征离线缓存；训练输出头时语言模型不再驻留显存。特征标准化只使用训练字符计算逐维均值与标准差，然后应用于验证和测试特征。

### 4.2 损失与选择

- 主损失：加权 `BCEWithLogitsLoss + 0.5 × Dice Loss`。
- 优化器：AdamW。
- 学习率：0.001。
- weight decay：0.0001。
- batch size：256。
- 最大 epoch：300。
- early stopping patience：15。
- 二值阈值：只在验证集的 0.05～0.95 网格上按前景 F1 选择。
- 置信区间：按测试字符 bootstrap 1,000 次，报告 95% 区间。

### 4.3 对照实验

1. `last_hidden`：正式主实验。
2. `input_embedding`：判断信号在进入模型层前是否更强。
3. `shuffled_labels`：保留最后层特征，但随机打乱训练字符与字形标签的对应关系。
4. `mean_glyph`：所有测试字都输出训练集的逐像素平均字形。

## 6. 分析

### 6.1 最后层存在字符特异信号，但不是高质量重建

`last_hidden` 的检索 Top-1 为 7.03%，其置信区间下界 5.33% 仍远高于随机机会 0.12% 和打乱标签对照。这证明输出并非只是在画一个通用汉字轮廓；预测点阵保留了可用于区分目标字形的结构。

但是，前景 F1 只有 0.4598，Exact Match 为 0。当前结果不能支持“只替换输出层即可准确输出 32×32 汉字点阵”这一强结论。

### 6.2 输入 Embedding 比最后层更强

输入 Embedding 的 Top-1/Top-5 为 19.76%/40.12%，最后层只有 7.03%/17.09%；Embedding 的 F1 和 Hamming 也更好。这说明 Qwen3.5 的 Token Embedding 中存在较强的字符身份信息，而最后层为语言建模目标进行变换后，这种线性可恢复的几何信息有所衰减。

这不等同于证明 Embedding 直接编码了部首或笔画。Token 身份本身也可以与固定字形形成统计映射，后续仍需用 IDS 构件不重叠拆分区分“字符查表结构”与“部件组合泛化”。

### 6.3 平均字形说明 F1 不能单独使用

平均字形基线通过覆盖大多数汉字共享的居中方块与常见笔画区域，取得 0.9185 Recall 和最高的 0.5804 F1，但检索准确率恰好处于随机水平。它并不知道目标是什么字。

因此，本项目必须同时报告前景重建指标和最近字形检索。只报告 F1 会错误地把“通用汉字形状模板”判断为优于包含目标身份信息的预测。

### 6.4 字频结果需谨慎解释

本轮低频和中频桶的 F1 没有低于高频桶，甚至略高。可能原因包括不同字频桶的平均笔画密度和复杂度不同，也可能是 tokenizer 的单 Token 筛选造成选择偏差。在加入笔画数、部首和 IDS 结构元数据前，不能把该结果解释为模型对生僻字泛化更好。

## 7. 结论

本轮得到的是“部分支持、强重建目标不成立”的结果：

- 支持：冻结 Qwen3.5-2B 的输入 Embedding 和最后层隐藏状态中都存在可被线性头读出的字符特异信号，并能泛化到没有参与输出头训练的字符。
- 不支持：最后层线性输出头尚不能忠实恢复 32×32 二值汉字；测试集没有任何 Exact Match，F1 也没有超过平均字形模板。
- 新发现：输入 Embedding 比最后层更容易解码，说明研究下一步应做分层探针，而不是只测试最后一层。
- 方法学发现：平均字形能获得很高的 F1，却没有任何字符识别能力；最近字形检索是不可省略的指标。

## 8. 限制

1. 本轮只运行 Qwen3.5-2B-Base，不能直接外推到 4B 主模型或 Qwen3 文本对照。
2. 拆分按字符身份随机进行，还没有基于 IDS 做“部件已见、组合未见”的严格拆分。
3. 输入就是目标汉字本身，尚未测试“纯中文上下文预测下一个汉字点阵”。
4. 只使用一种字体和一个二值阈值，未测试跨字体泛化。
5. 最近字形 gallery 只包含 825 个测试字符，不是完整 Unicode 汉字集合。
6. 本轮只能证明线性可读的字符特异信息，不能单独证明模型内部显式表示了象形结构。

## 9. 下一步实验

优先级建议如下：

1. 在 Embedding、25%、50%、75% 和最后层训练相同探针，定位字形信号随深度的变化。
2. 下载并运行 Qwen3.5-4B-Base 与 Qwen3-4B-Base，在两个 tokenizer 的单 Token 交集上比较。
3. 引入 CHISE IDS，建立部件组合不重叠测试集，区分字符身份信息与真正的构件泛化。
4. 在中文维基上下文上构建“前缀 → 下一汉字点阵”任务，目标字不出现在输入中。
5. 加入第二字体作为域外测试，确认探针恢复的是字形结构而不是固定字体像素模板。

# Qwen3.5-2B 汉字字形解码瓶颈诊断报告

## 1. 结论摘要

本轮完成了六组诊断实验，用来解释为什么冻结 `Qwen3.5-2B-Base` 后，仅训练 `Linear(2048, 1024)` 仍不能忠实恢复未见汉字：

1. 见过字符的训练集容量上限。
2. Embedding、25%、50%、75% 和最后层的分层线性探针。
3. 线性输出头与两层 MLP 输出头对比。
4. CHISE IDS 结构、康熙部首和笔画数多任务辅助监督。
5. 二值点阵与抗锯齿灰度目标对比。
6. 64 维字形自编码器，以及语言特征到固定字形 latent decoder 的实验。

最终根因不是单一的“线性头太小”，而是以下问题的组合，其中第一项是主要瓶颈：

- **主要瓶颈：原子汉字 Token 的表示缺少对未见字符可泛化的显式部件和空间布局信息。** 模型知道字符身份，但不同字符的向量没有形成“部件 → 位置 → 笔画像素”的稳定几何坐标系。
- **表示层选择错误：最后层不是字形信息最强的层。** 输入 Embedding 的字符检索 Top-1 为 19.76%，最后层仅为 7.03%；语言建模层明显削弱了字符身份信号。
- **输出头容量是次要问题。** MLP 能在见过字符上达到 F1 0.9984、Exact Match 93.44%，证明它有能力记住映射；但在未见字符上 Top-1 只有 0.48%，并没有学会构件组合。
- **硬二值目标会增加难度，但不是根因。** 灰度监督把最后层线性 F1 从 0.4598 提升到 0.4997，仍远低于可靠重建。
- **简单辅助标签不足以建立空间组合机制。** 多任务头能预测结构、部首和笔画数，却没有显著提高点阵 F1。
- **字形 decoder 不是主要瓶颈。** 自编码器可以在未见测试字上取得 F1 0.8713、检索 Top-1 100%；从语言特征预测同一 latent 后却只剩 F1 0.5850、Top-1 1.33%。

因此，当前失败发生在“语言表示 → 可组合字形几何表示”这一步，不是字体渲染错误、训练代码错误，也不是 decoder 根本画不出汉字。

## 4. 实验一：见过字符容量上限

### 4.1 目的

判断问题是否来自训练实现、32×32 标签错误或输出头根本没有能力表示汉字。

### 4.2 结果

- 线性头：F1 0.8357，Top-1 98.44%，但 Exact Match 为 0。
- MLP：F1 0.9984，IoU 0.9969，Exact Match 93.44%。

### 4.3 解释

训练、渲染、损失和评测管线没有系统性错误；一个只位于输出侧的 MLP 完全有能力画出点阵。线性层对于精细像素映射容量不足，但它已经能识别绝大部分见过字符。

未见字符 MLP 与见过字符 MLP 之间的巨大差距说明：真正困难的是从其他字符推导新字符，而不是记忆已有映射。

## 5. 实验二：分层线性探针

### 5.1 结果

- 字符身份检索最强的是 Layer 0：Top-1 19.76%、Top-5 40.12%。
- 前景像素 F1 最强的是 Layer 12：F1 0.5353。
- 最后层最差：F1 0.4598、Top-1 7.03%。

### 5.2 解释

Embedding 保留了最多的 Token 身份信息，中间层更容易预测“一个典型汉字应该在哪些区域有笔画”，最后层则主要服务于下一 Token 语言建模。

所以把最后层作为唯一字形特征是错误的。身份检索与平均像素重建的最佳层不同，也说明下一版应该融合浅层和中层，而不是寻找一个万能单层。

## 6. 实验三：MLP 非线性输出头

未见字符 MLP 把 F1 从线性头的 0.4598 提高到 0.5889，但检索 Top-1 从 7.03% 降到 0.48%。其 Recall 达到 90.88%，说明 MLP 主要输出覆盖广泛的通用汉字轮廓，从而提高像素 F1，而没有正确恢复目标身份。

这证明单看 F1 会产生误导。非线性容量可以学习更好的平均模板并记忆见过字符，但不会自动产生未见部件组合能力。

## 7. 实验四：IDS、部首和笔画辅助监督

CHISE IDS 直接在服务器从官方仓库下载并固定：

- CHISE revision：`352e13378e411c322cfa16bfd7a6d21d670d7eca`。
- IDS 结构覆盖率：100%。
- 康熙部首覆盖率：99.98%。
- 笔画数覆盖率：100%。

辅助任务测试结果：

| 辅助任务 | 指标 |
|---|---:|
| IDS 布局结构准确率 | 66.55% |
| 214 类部首准确率 | 48.12% |
| 总笔画数 MAE | 2.29 笔 |

多任务点阵 F1 为 0.5892，相对相同共享 MLP 的 0.5889 只增加 0.0003；Top-1 从 0.48% 增至 1.58%，仍然很低。

原因是辅助分类只要求共享隐层“知道”结构类别、部首和笔画数，没有要求 glyph decoder 把“氵”“青”“左右结构”放到明确的空间位置。辅助监督产生了结构知识，但没有建立可执行的构件渲染程序。

## 8. 实验五：灰度监督

抗锯齿灰度目标中有 25.77% 的像素处于 0 和 1 之间。相比硬二值线性头：

- F1：0.4598 → 0.4997，增加 0.0399。
- Top-1：7.03% → 8.61%，增加 1.58 个百分点。
- Hamming：0.3613 → 0.3299。

硬阈值确实放大了单像素偏移和边缘误差，但消除它之后仍无法可靠恢复字符，因此它是次要瓶颈。

## 9. 实验六：字形自编码器 latent

### 9.1 字形生成器上限

只在训练字符上训练的 64 维卷积自编码器，对未见测试字符直接编码、解码时达到：

- F1 0.8713。
- IoU 0.7720。
- Hamming 0.0751。
- 检索 Top-1/Top-5 100%/100%。

这证明一个很小的字形 decoder 就能表达测试字形，并能保持字符身份。Exact Match 仍为 0，说明 64 维 latent 和 32×32 硬二值化对逐像素完全一致仍然苛刻，但不是字符识别瓶颈。

### 9.2 语言特征预测 latent

使用最后层语言特征预测同一个 64 维 latent，再交给冻结 decoder：

- F1 降至 0.5850。
- Top-1 降至 1.33%。
- 最佳 epoch 只有 2，随后验证误差恶化。

同一个 decoder 在拿到真实字形 latent 时 Top-1 100%，拿到语言预测 latent 时只有 1.33%。因此问题明确发生在语言向量到字形几何空间的映射，而不是 decoder 画不出来。

## 10. 最终问题定位

当前架构：

```text
原子汉字 Token
  → 最后层语言隐藏状态
  → 全局线性/MLP 映射
  → 1024 个像素
```

存在三个结构性缺陷：

1. **输入是原子身份，没有显式构件。** 输出头只能从训练字符之间的统计相似性猜测新字，无法可靠执行“氵 + 青 + 左右布局 → 清”。
2. **最后层优化目标与字形不一致。** 它面向下一 Token 预测，把 Embedding 中较强的字符身份信息转换为语义和语言预测特征。
3. **输出头没有空间组合归纳偏置。** 全连接层能记忆像素，也能生成平均汉字模板，但没有“部件、布局、局部笔画”的显式生成过程。

线性容量、二值边缘和 decoder 表达能力都会影响数值，但实验已经证明它们不是主要原因。

## 11. 下一版架构建议

如果继续保持预训练骨干全部冻结，建议将输出侧改为：

```text
Token Embedding ───────────────┐
                              ├─ 多层融合 ─ 构件/布局 latent ─ 空间 decoder ─ 灰度图 ─ 二值化
50% 深度隐藏状态 ─────────────┘
```

具体顺序：

1. 融合 Layer 0 和 Layer 12：前者提供字符身份，后者提供更好的平均像素信号。
2. 输出头先预测 IDS 结构、部首/部件槽位和空间布局，而不是只增加辅助分类损失。
3. 将预测的部件嵌入按左右、上下、包围结构放入二维 feature map。
4. 使用卷积 decoder 生成抗锯齿灰度图，最后再选择二值阈值。
5. 训练和测试必须增加 IDS 部件组合不重叠拆分，验证是否真正学会新组合。

需要特别说明：如果严格要求输入侧永远只有一个原子 Token，且不允许向输出头提供任何 IDS/部件信息，那么未见字符泛化的上限很可能持续很低。仅把线性层换成更大的 MLP，会改善视觉平均形状和记忆能力，但实验已经表明它不会自动获得部件组合能力。
