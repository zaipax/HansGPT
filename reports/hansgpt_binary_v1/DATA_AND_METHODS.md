# HansGPT binary v1：数据、方法与复现附录

本附录依据实际运行导出的 [reproducibility.json](reproducibility.json)、[实验协议](../../BINARY_GPT_EXPERIMENT.md)、[语料处理说明](../../CHINESE_CORPUS_PILOT.md) 与 [模型实现](../../src/hansgpt_research/glyph_lm.py)，说明模型、数据身份、固定训练配置及启动前检查。训练实际终止预算、最终测试指标和自由生成效果由主报告另行记录。

## 模型与监督目标

HansGPT binary v1 从随机权重开始，字形编码器、因果 Transformer 和像素预测头全部联合训练。它没有加载 Qwen 或其他预训练模型，也没有冻结语言骨干；这是新的字形语言建模实验，与此前冻结模型的字形探针实验不同。

每个序列位置输入一个 `uint8[1,32,32]` 格子，元素严格为 0 或 1。共享 CNN 将其映射为一个 768 维向量，因果 Transformer 利用前文预测下一格的 1024 个像素 logits。训练采用真实前文的 teacher forcing；对真实下一格计算未加权的逐像素 `BCEWithLogits`，先平均一格内的 1024 个像素，再按有效目标格数归一化。Padding 不参与损失。

```text
前文的 32×32 二值格子
  → 共享 CNN → 每格一个 768 维向量
  → 因果 GQA Transformer
  → Linear(768, 1024) → 下一格的 1024 个像素 logits
```

生成接口逐像素 sigmoid 后按阈值二值化，得到严格的 0/1 格子，再送入同一个 CNN。1024 个像素构成一个序列 Token；输出不是字符类别。最近字形检索或可读文字导出不进入生成反馈，不能用检索替换后的字形评价原始生成效果。

| 部分 | 实际结构 | 参数数 |
|---|---|---:|
| 字形编码器 | 四层无偏置 3×3 卷积，通道 `1→32→64→128→128`，步长 `1/2/2/2`；每层 GroupNorm（8 组）和 SiLU；`128×4×4` 展平后无偏置投影至 768，再 RMSNorm | 1,814,240 |
| 因果 Transformer | 12 层、隐藏维 768；12 个 Query 头、4 个 KV 头，每头 64 维；SwiGLU 中间维 2048；RoPE、RMSNorm、SDPA | 75,516,672 |
| 像素头 | 带偏置 `Linear(768,1024)` | 787,456 |
| 合计 | 运行元数据实测参数总量，与上述结构核算一致 | **78,118,368** |

模型使用 Transformers 的 `LlamaModel` 组件，但显式移除了 `embed_tokens`，只通过 `inputs_embeds` 接收 CNN 输出；没有字符 ID 嵌入或字符分类头。GroupNorm 在单个格子内部归一化，不跨序列位置混合统计。注意力及 MLP 不使用偏置，注意力 dropout 为 0，RMSNorm ε 为 `1e-6`，RoPE θ 为 `10000`。配置中的初始化标准差 `0.02` 用于 Transformer 和显式初始化的像素头；CNN 使用其模块初始化方式，不能把全部权重都描述为同一种正态初始化。

模型配置的位置容量为 **2048 格**，本次实际训练块长为 **1024 格**。两者不是同一字段。长度较短的批次裁去共同尾部 padding，并向 8 的倍数对齐，且不超过 1024 的训练块上限。段落之间不串接上下文；长段落分块时保留边界所需的相邻格，使每个下一格目标恰好被计入一次。

实际启用 `packed` 字形去重：同一次前向中，按完整二值像素相等关系去重，编码后回填各出现位置，反向传播累加这些位置的梯度。128 字节的无损打包仅用于比较相等性；CNN 仍接收原始 1024 个二值像素。该缓存不跨参数更新保存，不构成可学习的字符嵌入表。CNN 每次编码至多 256 个不同格子。

## 数据来源、许可与清洗

服务器直接从 ModelScope 的 `AI-ModelScope/wikipedia` 下载 `20231101.zh`，对应 **2023 年 11 月 1 日中文维基快照**。六个 Parquet 分片合计 **1,721,150,260 字节**，共 **1,384,748 行**。实际扫描数逐分片与 Parquet 元数据一致，六个分片均标记完成；没有页面数或汉字数截断。

镜像文件修订固定为 `af6f00069c4a886b60b7b08d80882efde42c5432`；上游为 `wikimedia/wikipedia`，对应仓库修订 `b04c8d1ceb2f5cd4588862100d08de323dccfbaa`。六个文件的大小和 SHA-256 见聚合元数据及 [来源配置](../../configs/datasets/modelscope_wikipedia_zh.json)。下载完成后核验固定大小及内容哈希，原始文件保留在服务器。

ModelScope 元数据的 Apache-2.0 标签与上游卡片描述的 Wikipedia **CC BY-SA／GFDL** 不一致；镜像标签不替换底层正文许可。数据记录保留页面 ID、页面 URL 和归属信息，公开再分发仍须检查页面适用权利。上游 Parquet 已是提取后的正文，字段为 `id/url/title/text`；本管线不再次按 wikitext 解析。由于源行没有文章修订 ID，`source_revision_id` 如实保留为空，快照日期、来源文件和文件修订另行记录。

本次采用 `strict_han_v3_artifact_rejection`：

1. NFC、显式标点映射及首尾空白清理；先拒绝不允许的字符，再执行固定 OpenCC `t2s`，转换后再次检查。
2. 正文只保留汉字（含“〇”）及明确允许的中文标点。夹杂阿拉伯数字、外文、内部空格或其他符号的段落整段拒绝；不删掉中间内容再拼接，也不猜测数字或术语改写。
3. 每段至少 40 个汉字、至多 4096 个字符；拒绝连续十次重复字符及不可渲染段落。
4. 针对烟测观察到的源提取残缺，整段拒绝空／纯标点括号、显式标签空值（如“（学名：）”）和明确缺失数值的句式（如“面积，位于法国”）。标签及地理前缀采用显式名单。
5. 全局精确去重和近重复筛选后，以来源页面 ID 和种子 `20260907` 的哈希约按 98%／1%／1% 拆分。

“纯中文”在这里指**汉字加允许的中文标点**，不等于只保留汉字而删除所有标点。字符规则也不等于统计语言识别；全汉字的日语引用等仍可能通过。

|---|---:|
| 候选段落 | 28,030,704 |
| 非中文或不支持符号 | 13,994,247 |
| 汉字数不足 | 12,737,605 |
| 空／纯标点括号 | 326,039 |
| 标签空值括号 | 45,092 |
| 明确缺失数值 | 301 |
| 不可渲染 | 1,633 |
| 精确重复 | 8,104 |

| **保留** | **915,748** |

上述互斥拒绝类别与保留量合计等于候选数，段落保留比例约 **3.267%**。候选字符共 1,004,928,262 个；这项计数包含随后被拒绝的段落及其符号，不能当作最终训练字符数。`rejected_before_opencc` 是非中文拒绝量的处理阶段记录，不应再加到拒绝总数中。严格过滤会明显改变领域分布，尤其减少数字密集、外文术语密集的百科内容；保留比例不代表剩余文本达到同等比例的质量提升。

精确去重同时检查规范文本及去标点后的汉字序列。近重复候选取汉字五字片段的八个最小 CRC32 哈希，要求至少共享两个锚点、长度比约不低于 0.9；按共享锚点数排序后最多核验一百条候选，真实片段集合 Jaccard ≥ 0.9 才删除。CRC32 只产生候选，不单独证明重复。实际候选上限触发 **3,057 次**，因此不能称为穷举近重复去重。

## 拆分规模、字形与有效目标

| 集合 | 段落 | 来源页面 | 汉字 | 存储格子（含 BOS/EOS） | 每遍有效下一格目标 |
|---|---:|---:|---:|---:|---:|
| 训练 | 897,245 | 296,257 | 85,236,554 | 96,557,521 | **95,660,276** |
| 验证 | 9,162 | 3,047 | 875,491 | 988,590 | **979,428** |
| 测试 | 9,341 | 2,996 | 897,588 | 1,015,363 | **1,006,022** |

每段存为 `[BOS, 正文格子…, EOS]`，因此有效下一格目标数等于存储格子数减段落数；它包括正文和 EOS，不包括 BOS 或 padding。全数据共保留 **87,009,633 个汉字**，另含标点。训练集正文的汉字与标点共 **94,763,031 个字符**。

正式配置声明 **1,500,000,000 个有效下一格目标**的预算，相当于约 **15.6805 次**训练集有效目标的重复呈现。它不是十五亿个独立字符，也不是新增十五亿语料。实际成功更新量、溢出时尝试量和遍历次数应分别读取训练终止记录；配置预算本身不证明已经完成训练。

字形由 **Noto Sans CJK SC Regular 2.004** 直接从官方仓库下载，遵循 **SIL OFL 1.1**。固定字号 26、基线 y=27、32×32 画布及灰度阈值 128，输出只取 0／1；较大辅助画布用于检测裁切。字体 SHA-256 为：

```text
2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b
```

字形库为 `uint8[11923,32,32]`，其中 **11,919 种内容字符包括汉字和标点**，另有四种控制格 `PAD/BOS/EOS/NEWLINE`（地址 0／1／2／3）。PAD 是全零格；其余控制格为固定的边框及内部二值图案。NEWLINE 不作为正文序列中的目标使用，段落边界通过 BOS/EOS 表达。存储的 `uint16` 值只寻址字形资产，模型输入时已还原成像素。

实际记录 **546 种不可渲染字符**，涉及拒绝的 1,633 段。内容字形存在一组完整像素碰撞：**“㮣”与“槩”**。这些字符的视觉输入相同，不能据此区分字符身份；检索与匹配解释必须保留碰撞影响。

拆分保证同一来源页面不跨集合，并在全局去除确认的重复段落，但没有保证重复作品的整个连通组不跨集合。相同汉字可以出现在三个集合中；这一实验衡量单字体、页面留出的下一格建模，**不能证明未见汉字、未见部件组合或跨字体泛化**。

## 环境、训练配置与复现身份

实际训练设备为用户指定的 **GPU 0，Tesla V100S-PCIE-32GB**。运行元数据记录 PyTorch `2.8.0+cu128`、CUDA runtime `12.8`、FP16，以及 `CUDA_VISIBLE_DEVICES=0`；启动协议同时设置 `CUDA_DEVICE_ORDER=PCI_BUS_ID`。项目环境由 uv 管理，依赖按锁文件同步；这一 CUDA runtime 版本不是系统 CUDA Toolkit 或 NVIDIA 驱动版本的声明。

| 固定项 | 实际配置 |
|---|---|
| 随机种子 | 20260907 |
| 训练块长／microbatch／梯度累积 | 1024／64／4 |
| 采样 | `sortish` v1，每池 64 个批次，按长度减少 padding，保留全部块及恢复游标 |
| 优化器 | AdamW，β=(0.9,0.95)；二维及以上参数 weight decay=0.1，norm 与 bias 不衰减 |
| 学习率 | 峰值 3e-4；按有效目标数预热 10,000,000，再余弦衰减至峰值的 0.1 |
| 梯度与精度 | FP16 autocast、GradScaler；梯度范数裁剪 1.0；梯度检查点启用 |
| 数据加载 | 2 个 worker |
| 声明预算 | 1,500,000,000 个成功更新对应的有效目标；最大 1000 遍；早停关闭 |
| 验证／保存 | 每约 10,000,000 个有效目标验证；每 200 个更新保存检查点；每 10 个更新记录训练日志 |
| 评估配置 | batch 32；二值阈值候选 0.25 至 0.75、步长 0.05；检索块为 query 256／gallery 2048 |

64×4 表示一次更新最多累积 256 个文档块；由于段落长度和 padding 不同，不能把每次更新都按 `64×4×1024` 个有效目标计算。GradScaler 跳过的更新计入尝试量及溢出记录，不计入有效预算。仅当完整验证 BCE 比已保存值下降超过 `1e-5` 时替换最佳检查点；二值阈值依据完整验证集内容目标（汉字与标点，排除控制格）的前景像素 micro F1 选择。测试拆分不参与这两项选择。

BCE 的单位为 **nats/pixel**，每格 NLL 是它的 1024 倍，不是字符词表语言模型的困惑度。F1／Dice 汇总所有受评前景像素的 TP／FP／FN 计算，为 micro F1，二者在本实现中相同；它们不是字符准确率。完整点阵匹配、字形库检索和自由生成语义质量分别解释。

实际软件版本还包括 NumPy `2.5.2`、Pillow `12.3.0`、Transformers `5.16.1`；语料环境记录 PyArrow `23.0.1`、fontTools `4.63.0`、mwparserfromhell `0.7.2`、regex `2026.7.19`、OpenCC Python `0.1.7`，Unicode 规范化数据库版本 `15.0.0`。原始训练 metadata 未单独记录 Python 补丁版本及驱动版本；在 `2026-09-08T06:35:59Z` 从同一项目环境与 GPU 0 只读补查得 Python `3.12.13`、NVIDIA 驱动 `535.183.01`，作为环境补记单独列入聚合元数据。正式报告绘图使用临时 uv 附加环境的 Matplotlib `3.10.8`，不修改训练依赖锁文件。

## 预检覆盖与解释边界

数据验证凭据显示：全部源行计数、输出哈希、纯中文字符约束、已知提取残缺、逐像素二值性、完整字形重渲染、索引、控制格、碰撞分组、逐段序列、页面拆分、精确及标点变体去重、来源文件与汇总计数检查均通过。

独立污染抽检固定选取 32 个验证和 32 个测试段落，将其与全部 **897,245 个训练段落**比较汉字五字片段集合 Jaccard，阈值 0.9，发现 **0 个被标记的留出样本**。这只覆盖 64 个样本及该相似度定义；不能据此认定全部留出集不存在近重复、语义污染或外部评测泄漏。

实验协议还记录了两项启动前检查：相同完整训练数据与顺序上的 packed／unpacked 短基准各更新 411,789 个有效目标，验证 BCE 差约 `5×10⁻⁸`；包含检查点和小规模验证的用时分别约 17.92／19.68 秒。另一次 64×1024 全有效位置容量检查完成两次 FP16＋AdamW 更新，CNN 梯度有限且权重变化，无溢出，峰值分配／保留约 23.24／24.93 GiB。它们证明受检配置能执行更新，不是正式训练指标、完整验证结果或最终吞吐保证。

早先错误地把 PAD 当有效正文的容量检查曾发生首次梯度溢出；协议保留该失败及纠正后的测试范围，不能将后续通过扩大为任意全零输入都稳定。语料方面，已知空值模式被整段拒绝，但上游已删除的信息无法由字符过滤恢复；源快照较旧、百科领域集中，也未完成全面人工质量审核或外部基准去污染。上述限制应与最终效果一起解释。
